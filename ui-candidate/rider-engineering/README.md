# RIDER-TEST-01 — 騎手受控模擬工作台

2026-11-12。核准範圍：指定測試環境整批實作、部署及模擬資料驗收；正式營運鎖定。

## 本批實際交付

- 會員中心內工作台；原 LOGO、Banner、四大分頁不變。
- 兩個既有已註冊測試會員各自持有隔離的工作區；工作區內有模擬騎手 A/B、總部、收件端。
- 模擬資格申請、補件、人工核准、良民證更新、逐台車輛核准與授權撤回。
- 僅由伺服器生成印有 TEST 的 PNG 範例證件；沒有接受使用者真實證件的檔案輸入或 API。
- 模擬派單、指定實際車輛、接單、核袋與封袋確認、取件、交出、收件端簽收回執。
- 異常回報、總部恢復原階段、取件前改派或取消；取件後禁止直接取消或靜默改派。
- 固定順序多點路線預覽（手機最多四點）、下一站機車導航。Google URL 請求 `two-wheeler` 與 `dir_action=navigate`，實機仍可能要求再按開始；不宣稱已驗收。
- 任務、操作者、車輛與時間構成交接稽核；本批沒有新增現場取件照片拍攝功能。
- 費率狀態固定 `rate_not_set`；沒有應付款、匯款或實際騎手收入。

## 隔離與權限

`lx_rider_private` 七表：workspaces、people、vehicles、documents、tasks、events、commands。
全部啟用 RLS，客戶端無表格權限。三個公開 RPC 僅 service_role 可呼叫；角色/所有權檢查在私有函式執行。

`rider-test-api`（JWT gate 開啟）再次用 Auth getUser 驗證、限定既有兩個 Google 測試會員，並由伺服器帶入身分。禁止客戶端指定真實 user_id、上傳位元組或授予工作角色。

**切換模擬角色不是實際工作帳號的 RBAC 登入。** 不會將既有私人會員提升為總部或騎手；不會改動真實工作資格、分享袋或派車資料。本批任務編號一律 TEST 開頭，座標是固定的公共區域模擬目的地，不代表已核准取件點，不需實際前往。

工作區交易鎖序列化狀態變更；revision 拒絕過時資料；command UUID 綁定完整要求，重送同一指令回傳原結果，改內容重用 UUID 拒絕。前端重查身分並抑制換帳後舊回應。

## 證件與清理

`rider-test-documents` 為私密 bucket，PNG 上限 2,000,000 bytes，沒有任何客戶端 Storage policies。這只是伺服器產生的範例，不能據此視為真實證件已完成清晰度驗收。放置點照片仍維持原本 100,000 bytes。

範例文件閱覽經資料庫重新授權後簽發 60 秒 URL，記錄閱覽事件；連結已到期或文件已超過刪除期限時不再簽發。已審核/過期圖片不得用舊上傳指令重新建立。

良民證/駕照/行照範例審核後設定 30 日刪除日期；車主授權有效期間保留，終止後保存期限尚未核定，不擅自填值。每次呼叫只清理當前帳號到期的範例，先經 Storage API 實體刪除、確認 metadata 不存在後才記錄 deleted_at；法律保全排除清理。

**未啟用無人值守的每日刪除排程。** 本批是「到期拒絕新閱覽＋存取時清理」，不等於保證第 30 天無人登入時也已實體刪除。正式收件前須驗收排程、保全與合作終止後 3 年的必要結果保存制度。

審核目標日期排除週末，尚未套用台灣國定假日日曆。30 天內到期提示由後端提供；精確 30/14/7 日主動通知排程未啟用。沒有簡訊或郵件。

## 手機驗收順序

1. 測試站 Google 登入 → 會員中心 →「樂享騎手｜受控測試工作台」→ 建立本人模擬工作區。
2. 模擬騎手 A：建立駕照及良民證範例、新增機車、建立行照及車主簽名授權範例，確認模擬說明後送出申請。
3. 模擬總部：先閱覽範例圖片，核准騎手與機車；建立任務、指定騎手與車輛並派單。
4. 模擬騎手 A：接單、模擬掃描袋號、確認封袋並取件，再交出袋件。
5. 模擬收件端：核對袋號並簽收，應產生回執；重新整理應還原。
6. 模擬騎手 B：不得看見 A 的派單；另一個 Google 帳號應是獨立工作區。這仍不等於正式工作帳號角色驗收。
7. 驗證撤回單台車、良民證到期、異常恢復、錯袋號、重送、手機 Maps 與返回資料保留。

## 正式開放前仍鎖定的缺項

私人/工作 Google 帳號明確綁定與真實跨角色 Session 驗收；完整 CERT/LOG 的申訴與獨立複審規格；正式合作文件及本人同意；真實證件清晰度與必要個資範圍；保險及車輛營運條件；保全/刪除與提醒排程；車主授權終止後保留期限；費率與結算；既有分享袋/職人資格/派單串接；實際取件照片；路線最佳化。不能把本模擬版本當作已可正式接單。
